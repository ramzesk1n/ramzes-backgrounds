# Палитра и автоматическая связь с дизайн-системой · 0.2.0

## Ручная настройка

В галерее нет выбора из фиксированных палитр. Введи свои primary, secondary, accent, background, surface, text, muted, border, highlight и on-image. Для HEX можно использовать цветовой пикер, для RGB/HSL/OKLCH — текстовое поле. В разделе импорта можно вставить JSON и скачать текущую конфигурацию. Значения tokens нужны для предпросмотра и как запасные цвета. bindings — имена реальных CSS-переменных сайта.

Каждый материал использует подходящие роли. Сетка и чертёж берут primary, фактуры и тени — secondary, аврора — primary/secondary/accent, стекло — surface/border/highlight/accent, водные блики — highlight. background задаёт основу, text — текст примера, on-image — текст на тёмном мраморе. Не каждый материал использует все десять цветов.

## Подключение к проекту

```bash
python3 scripts/backgrounds.py export quiet-aurora --out /absolute/project/backgrounds/aurora --tokens /absolute/project/design-system/background-tokens.json
```

Пример конфигурации — theme.example.json. Если в проекте основной цвет называется --color-brand-primary, используй bindings.primary="--color-brand-primary". Экспорт запишет:

```css
.rb-surface {
  --rb-ink: var(--color-brand-primary, #38534a);
  --rb-bg: var(--color-page, #f2ece0);
  --rb-accent: var(--color-accent, #a36945);
}
```

Основной рецепт читает --rb-*; если переменная сайта меняется в :root, [data-theme] или родительской секции, подложка меняется автоматически средствами CSS. Контекст темы должен быть на предке секции или на самой секции. Обновление токенов в другом, не связанном DOM-поддереве не влияет на неё.

**В production подключай background.css к существующей дизайн-системе.** theme-example.css нужен только отдельному example.html: он определяет пример токенов и не должен переопределять реальную тему сайта. Зафиксировать отдельный локальный цвет можно старыми параметрами --bg/--ink/--accent, но это намеренно отключает живую связь для соответствующего слота.

## Что должен сделать агент

1. Найти источник палитры: глобальные CSS-переменные, tokens.json, Tailwind @theme/config, styles/theme, документацию дизайн-системы. Прочитать применимые AGENTS.md и локальные правила.
2. Определить смысл цветов, существующие светлую/тёмную темы и контекст секции. Не выбирать новый брендовый цвет при наличии готового.
3. Сопоставить роли и имена переменных. Для вычисляемых цветов сохранить исходную CSS-привязку; запасной цвет можно взять из нужной темы.
4. Если значение хранится как сырые HSL/OKLCH-каналы, создать цветовой алиас, например --color-brand-primary: hsl(var(--brand-primary-channels)); и привязать подложку к нему. Сами каналы не являются CSS-цветом. Не делать неоднозначный regex-разбор всего CSS автоматически.
5. Записать tokens и bindings в JSON, экспортировать материал, подключить только background.css и ассеты.
6. Проверить обе темы и актуальную секцию. Не копировать пример :root поверх палитры сайта. Записать в lock значения, привязки и намеренные overrides.

При отсутствии явных токенов агент может создать небольшой семантический слой из уже используемых цветов; не менять палитру проекта без задачи. Локально вычисленные inline-стили с HEX вместо var() не подходят для автоматической смены темы.

## Ограничения

Полноценная перекраска действует на кодовые CSS/SVG-решения. У мрамора и цветной растровой призмы меняются окружение, интенсивность и текст, но исходные прожилки/спектр остаются частью изображения. Не применять тяжёлую перекраску на клиенте, чтобы скрыть это ограничение.

muted и text управляют цветами образца и доступны как слоты для интеграции. Цвет реального содержимого сайта остаётся частью его собственной типографики; декор не должен самовольно перекрашивать все дочерние ссылки и кнопки.
