# Архитектура библиотеки

Источники карточек — базовая функция catalog() в build.py и расширение extended.py. Нишевые подборки задаются niches.py. Сборка создаёт catalog.json, recipes/*.css, assets/* и самодостаточный index.html. Галерея содержит каталог и data URL; сайт клиента их не получает. scripts/backgrounds.py работает с готовым JSON, не требует Pillow или сборки.

Три режима размещения: repeat, cover, overlay. В пилоте seamless=true только у шести периодических материалов. Каталог содержит описание, ниши, аргументацию, ограничения, совместимые позиции, настройки, происхождение, вес CSS gzip и ассета. Запись implemented означает, что рецепт существует; она не означает browser-verified или проверку на реальном телефоне.

Экспорт копирует один CSS, только упомянутые в нём ассеты, пример HTML и lock-файл. Прозрачность задаётся псевдоэлементу. Контент не получает opacity/filter. Общий класс rb-surface необходимо переименовать, если на странице используются несколько разных рецептов. Положение регулируется --rb-position, масштаб плиток — --rb-scale, цвета — --rb-bg/--rb-ink/--rb-accent, интенсивность — --rb-intensity.

SVG-паттерны используют конечную геометрию и alpha-маску, без feTurbulence, feGaussianBlur, внешних скриптов и изображений. Стекло — имитация заливкой и краем, без backdrop-filter. Анимаций в версии 0.2.0 нет. Приоритет — нулевой JS у клиентской подложки и отсутствие постоянной вычислительной работы.

Ниши являются тегами, а не отдельными копиями одного материала. docs/source-inventory.json содержит 64 пункта исходного перечня; это реестр исследования, не 64 готовых ассета. Последующие волны расширяют families после удаления дублей и проверки применимости.

Skill устанавливается отдельно, с небольшим индексом и комплектом данных/экспортёра. Не загружать весь JSON в контекст при каждом запросе: сначала list с фильтром, затем show для 2–3 кандидатов. Общее ядро используется Claude Code и Codex; установщик размещает папку в обнаруживаемом каталоге каждого инструмента.

GitHub: публичный репозиторий https://github.com/ramzesk1n/ramzes-backgrounds содержит рабочие данные, SVG/WebP, CLI и переносимый skill. PNG-мастера сохранены в полном архиве. Автономная галерея создаётся scripts/build_gallery.py из существующих данных без обработки изображений. Обновление библиотеки не меняет готовые клиентские экспорты автоматически. Нативный skill сохраняется отдельно штатным механизмом Skills.

Версия 0.2.0 добавляет десять семантических токенов и живые CSS-привязки. scripts/theme.py валидирует JSON и формирует alias var(), theme-example.css нужен только отдельному примеру. Токены реального сайта не перезаписываются экспортируемым background.css. См. TOKENS.md.

## Версия 0.3.0

build.py объединяет базовые 16 карточек и 44 из extended.py. niches.py формирует 48 курируемых подборок. Готовые catalog.json/niches.json читаются CLI без зависимостей. Галерея отображает по 12 карточек и фильтрует поиск, семейство, нишу и размещение. На сайт экспортируется по-прежнему одно решение. Всего 16 CSS, 36 SVG, 8 WebP.

## Версия 0.4.0

optics.py добавляет 20 рецептов и 11 детерминированных SVG. build.py объединяет 16 + 44 + 20 карточек и вызывает optics.enrich для справочных связей. Всего 25 CSS, 47 SVG, 8 WebP; 56 нишевых маршрутов. source_notes.py воспроизводит разбор PDF и карту 52 тем; если исходные PDF недоступны, использует ранее зафиксированные имена/хеши в PDF_CROSSWALK.json. Эта операция не нужна для обычной сборки или экспорта. Галерея и CLI показывают дополнительные поля карточек; на сайт они не загружаются.

## Версия 0.5.0

materials.py добавляет 40 карточек: 30 кодовых (22 SVG, 8 CSS) и 10 WebP с PNG-мастерами. Пена строится периодической диаграммой Вороного через отсечение полуплоскостями, без внешних зависимостей. Вычисления выполняются при сборке, не в браузере клиента. Производные WebP записываются через временный файл и replace.

neon.py формирует 11 SVG-ореолов и CSS-описания 16 неоновых режимов. Метаданные c.neon отделены от c.css: обычный экспорт не переносит ореол. CLI подключает его только при --neon и сохраняет настройки в lock. Галерея использует ту же c.neon.css, отдельно показывает дополнительный вес. Живые роли и намеренные фиксированные цвета проверяются отдельно.
